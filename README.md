# RL-Based Adaptive Data Center Cooling Optimization

A research-demo-quality proof-of-concept that combines **real workload telemetry** (Alibaba Cluster Trace 2017) with a **physics-inspired thermal simulation** and **classical reinforcement learning** to learn adaptive cooling strategies for a data center.

## Key Points

> **This project uses real Alibaba workload data + a simulated thermal field.**
> The Alibaba trace provides CPU/memory utilization — it does **not** contain thermal measurements.
> Temperatures are generated by a physics-inspired model driven by the real workload signal.

## Dataset

**Source**: Alibaba Cluster Trace 2017 `server_usage.csv`

| Column | Description |
|--------|-------------|
| timestamp | Measurement time (60-second intervals) |
| machine_id | Physical machine identifier |
| cpu_util | CPU utilization (0–100%) |
| mem_util | Memory utilization (0–100%) |
| disk_util | Disk I/O utilization (0–100%) |
| load1/5/15 | Load averages |

The project uses a mini-slice: **36 machines × 1000 timesteps = 36,000 rows** (~2 MB).

When the real Alibaba dataset is unavailable, a synthetic dataset with realistic utilization patterns is generated (clearly labeled as synthetic).

## Dataset → Thermal Mapping

```
Alibaba CPU Utilization → Heat Generation Model → Thermal Simulation → Temperature Field
     (real data)                                    (physics-inspired)
```

- 36 machines are mapped deterministically to a 6×6 grid
- CPU utilization (80%) + memory utilization (20%) = workload heat signal
- Heat generation: `Q = workload_heat_coefficient × normalized_workload`
- Thermal model includes: neighbor diffusion, ambient pull, cooling, noise

## Environment Formulation

### State Space

The 6×6 grid is divided into 4 zones (each 3×3):

```
┌──────────┬──────────┐
│  Zone 0  │  Zone 1  │
├──────────┼──────────┤
│  Zone 2  │  Zone 3  │
└──────────┴──────────┘
```

State = `(z0_temp, z1_temp, z2_temp, z3_temp, z0_wl, z1_wl, z2_wl, z3_wl, hotspot_zone)`

- Temperature levels: cool(0), normal(1), warm(2), hot(3), critical(4)
- Workload levels: low(0), medium(1), high(2)
- Total: 5⁴ × 3⁴ × 4 = **202,500 states** (tractable for tabular RL)

### Action Space (8 actions)

| ID | Action | Description |
|----|--------|-------------|
| 0 | Uniform | Moderate cooling everywhere |
| 1-4 | Zone focus | Extra cooling in one zone |
| 5 | Mild hotspot | Dynamic targeting of hottest cells |
| 6 | Strong hotspot | Aggressive targeting of hottest cells |
| 7 | Eco | Minimal cooling (save energy) |

### Reward

```
R = safety_reward                    (+1 if no overheated cells)
  − overheat_penalty_per_cell        (−0.15 per cell > 35°C)
  − critical_penalty_per_cell        (−0.5 per cell > 55°C)
  − energy_weight × energy_fraction  (penalise cooling power used)
  + hotspot_improvement_bonus        (+0.5 × Δmax_temp improvement)
  − variance_penalty                 (−0.01 × temperature spread)
```

## Algorithms

1. **Q-Learning** — Off-policy TD(0), ε-greedy with decay
2. **SARSA** — On-policy TD(0), uses Q(s', a') not max
3. **Monte Carlo** — First-visit, episode returns, incremental mean
4. **Value Iteration** — Sampled transition model + Bellman sweeps
5. **Rule-Based Baseline** — Deterministic heuristic policy

## How to Run

### 1. Prepare Dataset

```bash
# Generate synthetic dataset (if real Alibaba data unavailable)
python -m data.prepare_dataset --synthetic

# Or with custom sizing
python -m data.prepare_dataset --synthetic --machines 36 --timesteps 1000 --seed 42
```

### 2. Train Agents

```bash
python -m experiments.train --algorithm q_learning --episodes 300 --seed 42
python -m experiments.train --algorithm sarsa --episodes 300 --seed 42
python -m experiments.train --algorithm monte_carlo --episodes 300 --seed 42
python -m experiments.train --algorithm value_iteration --episodes 300 --seed 42
python -m experiments.train --algorithm rule_based
```

### 3. Evaluate

```bash
python -m experiments.evaluate --seed 42
```

### 4. Launch Dashboard

```bash
streamlit run app.py
```

## Hosting & Deployment Guide

This application can be hosted online for free or in production using any of the following methods:

### Option 1: Streamlit Community Cloud (Recommended — Free & Instant)

Streamlit Community Cloud provides free, zero-config hosting directly from GitHub:

1. **Push to GitHub** (already configured with repository `Adishram/RL-Data-Centre-Cooling`):
   ```bash
   git push -u origin main
   ```
2. Go to **[share.streamlit.io](https://share.streamlit.io/)** and sign in with your GitHub account.
3. Click **"New app"**.
4. Configure the deployment settings:
   - **Repository**: `Adishram/RL-Data-Centre-Cooling`
   - **Branch**: `main`
   - **Main file path**: `app.py`
5. Click **"Deploy!"**
   - Streamlit will automatically read `requirements.txt`, install dependencies, load the pre-trained models from `models/`, and provide a permanent public HTTPS URL (e.g. `https://rl-data-centre-cooling.streamlit.app`).

---

### Option 2: Hugging Face Spaces (Free)

1. Go to **[Hugging Face Spaces](https://huggingface.co/spaces)** and click **"Create new Space"**.
2. Set Space Name (e.g., `rl-data-center-cooling`), license, and select **Streamlit** as the Space SDK.
3. Clone the space repository locally or connect it to your GitHub repository:
   ```bash
   git remote add hf https://huggingface.co/spaces/YOUR_USERNAME/rl-data-center-cooling
   git push hf main
   ```
4. Hugging Face Spaces will automatically launch the app from `app.py`.

---

### Option 3: Docker Deployment (Local, GCP Cloud Run, AWS ECS, Render)

A production-ready `Dockerfile` is included in the root directory.

1. **Build the container image**:
   ```bash
   docker build -t rl-datacenter-cooling .
   ```

2. **Run the container**:
   ```bash
   docker run -d -p 8501:8501 --name rl-cooling rl-datacenter-cooling
   ```

3. **Access the app**:
   Open `http://localhost:8501` in your browser.

4. **Deploy to Cloud Run / Render / AWS ECS**:
   - Push the Docker image to your container registry (Docker Hub, AWS ECR, or GCP Artifact Registry).
   - Set container port to `8501`.

---

### Option 4: Linux Cloud VM / VPS (Ubuntu, AWS EC2, DigitalOcean)

To run as a persistent background service on a Linux server:

1. **Clone and setup**:
   ```bash
   git clone https://github.com/Adishram/RL-Data-Centre-Cooling.git
   cd RL-Data-Centre-Cooling
   python3 -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```

2. **Run with systemd (Auto-start on boot)**:
   Create a service file `/etc/systemd/system/rlcooling.service`:
   ```ini
   [Unit]
   Description=RL Data Center Cooling Streamlit App
   After=network.target

   [Service]
   User=ubuntu
   WorkingDirectory=/home/ubuntu/RL-Data-Centre-Cooling
   ExecStart=/home/ubuntu/RL-Data-Centre-Cooling/venv/bin/streamlit run app.py --server.port 8501 --server.address 0.0.0.0 --server.headless true
   Restart=always

   [Install]
   WantedBy=multi-user.target
   ```

3. **Enable and start the service**:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable rlcooling
   sudo systemctl start rlcooling
   ```

## Limitations

- **Thermal model is simplified**: No CFD, no airflow dynamics, no rack-level modeling
- **Classical RL only**: No deep RL (DQN, PPO, etc.)
- **State discretisation**: Loses information vs continuous state
- **Single-objective**: Reward combines thermal + energy as a scalar
- **Synthetic dataset**: When real Alibaba data is unavailable
- **No real-time control**: Simulation, not connected to actual infrastructure
